# docs/tickets — チケット台帳 (起票の作法)

**正本はこのフォルダの `TK-###.md`。** `../TICKETS.md` は `npx cpos-kit tickets` が作る索引 (手で編集しない)。
AI はセッションの最初に `docs/TICKETS.md` を読み、上の行から着手する。

## 1 枚の形

```markdown
---
status: open        # open / 進行中 / 判断待ち / closed
weight: B           # A = 止まる / B = 困る / C = あとで
created: 2026-09-14
parent: TK-001      # 子のときだけ (1 段まで。孫は赤)
---
# TK-002: 送迎メモの一覧画面

背景: (1〜3 行)

## 受入条件
- 正常系: 事業所を選ぶと、その事業所の利用者のメモだけが出る
- 失敗経路: 権限の無い事業所 ID を渡すと 403 になり、hint が出る

## チェックリスト
- [ ] T1: /api/notes の一覧
- [~] T2: 画面 (実装済・未検証)
- [x] T3: manifest に resources 追加  ✅ 痕跡: test/app.test.mjs
```

起票は `npx cpos-kit tickets new <タイトル> [--weight A|B|C] [--parent TK-###]` (番号を採る)。

## 決まり (機械が見る: `npx cpos-kit tickets --check`)

1. 索引が本文とズレていたら赤 → `npx cpos-kit tickets` で作り直す
2. `進行中` は葉で 3 枚まで。4 枚目にしたければ先に 1 枚閉じる (同時に持てる本数を縛るのが優先度を見失わない唯一の機械的な手)
3. `closed` にするとき `[ ]` `[~]` が残っていたら赤 (「完了しました」の嘘を止める)
4. 子が全部 `closed` になるまで親は閉じられない (置き去りを名指しする)
5. 親が無い / 3 段目の子は赤

## 子チケットにするか、チェックリスト行にするか

- 同じセッションで終わる・痕跡が 1 つ → **チェックリスト行** (`- [ ] T1:`)
- セッションをまたぐ・`判断待ち` になりうる・別の人や別の AI がやる → **子チケット**
- 迷ったらチェックリスト行。「待てるか」が唯一の分かれ目

`判断待ち` が 14 日動かないと索引に「(N 日停滞)」と出る (赤にはしない)。

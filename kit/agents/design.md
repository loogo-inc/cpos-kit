## 画面の規約 (cpos-kit)

使う人は**現場の職員**。IT の人ではない。スマホと事務所の PC の両方で、仕事の合間に使う。
**`@cpos/kit/ui` の CSS を読み、下の class で組む。** 自前の CSS フレームワークを持ち込まない。
`<link rel="stylesheet" href="/cpos-ui.css">` (雛形は `/cpos-ui.css` を配信済み)。色を変えるなら **その後ろに** `theme.css` を読み、`--cpos-*` 変数だけ上書きする。

### ばらつかせない 17 の決め (アプリごとに変えない。ここが揃っていないと「使い方」が変わる)

| # | 場面 | **こうする** (一意) | やらない |
|---|---|---|---|
| 1 | 意思決定のボタン (保存・確定・送信・削除実行) | **右**。取消・戻る・破棄は**左**。`.cpos-actions` が右寄せにする | 左に置く / 画面ごとに変える |
| 2 | 主ボタンの数 | 1 画面に `.cpos-btn.primary` は **1 つだけ** | 主を 2 つ並べる |
| 3 | 検索の起動 | **打つたびに絞り込む (即時)。Enter も同じ結果。検索ボタンは置かない** (`.cpos-search`、300ms 待ってから) | 「検索」ボタンを押させる / 虫眼鏡だけ / Enter でしか効かない |
| 4 | 絞り込み | `.cpos-chip` を押した瞬間に反映。「適用」ボタンを置かない。選択中は色 + 太字 + `aria-pressed` | 適用ボタン / 色だけで選択を示す |
| 5 | 必須の表し方 | **ラベルの右に赤い「必須」の文字** (`.cpos-required`)。任意には何も付けない | 「*」/「(必須)」/ 色だけ / 任意に「(任意)」 |
| 6 | 入力の誤り | **その欄の直下に赤文字 1 行**「どうすればよいか」(`.cpos-error`) + 欄を赤枠。送信時は最初の誤りへ移動 | 画面上部だけ / ダイアログ / 消える通知 |
| 7 | 保存 | **保存バー** (`.cpos-savebar`): 1 文字でも直すと上に出て、保存するまで消えない。保存したら `.cpos-snackbar` で「保存しました」 | 行ごとの保存ボタンだけ / 黙って自動保存 / 保存したか分からない |
| 8 | 確認 | **取り消せない操作 (削除・送信・確定・締め) だけ** `.cpos-dialog` を 1 回。ボタンは動詞 (「削除する」「やめる」) | 保存にも確認 / 「OK・キャンセル」/ `window.confirm` |
| 9 | 状態の色と文字 | 状態は**必ず文字**を持つ (`.cpos-badge` に「済」「未記録」「要確認」)。色は補助 | 色だけ / アイコンだけ |
| 10 | 事業所 (作業対象) | **事業所単位のデータを見せる画面では、どの事業所のデータかが画面から分かること。** 切り替えられるアプリでは **2 手** (名前を押す → 一覧から選ぶ)。**置き場と固定はアプリが決めてよい** (`.cpos-appbar` に置けばアプリ名の隣。上に貼り付けるなら `.cpos-appbar.cpos-pinned`。`create` が「ヘッダに固定表示しますか」と聞く)。1 つの事業所しか扱わないアプリは**表示だけでよい** (切り替えを置かない) | どの事業所か分からない / 常時置いた選択肢が **1 タップで切り替わる** (スクロール中に触れて別の事業所のデータになる) / **右上に置く** (右上は自分の場所) |
| 10b | 事業所に関係ない画面 | **事業所を出さない。** 法人単位のデータ (`{ scope: 'organization' }`)・自分だけの設定・お知らせなどは、代わりに `.cpos-scope` で **「法人全体」「自分だけ」と書く** (何の範囲を見ているかは必ず分かるようにする) | 関係ない画面にも事業所の選択を置く (どのデータが事業所単位か分からなくなる) / 範囲を何も書かない |
| 11 | 空・0 件・権限なし | `.cpos-empty` に**理由 1 文 + 次の一手のボタン** | 空白のまま / 「データがありません」だけ |
| 12 | 値が無い項目 | **「未設定」と書く** | 空欄 / 「-」/「null」 |
| 13 | 行き先 (グローバルナビ) | 画面が 2 つ以上なら **`.cpos-nav` を必ず出す**。行き先は **5 つまで**、いまいる所は色 + 太字 + `aria-current="page"`。**狭い幅は画面の下に固定、広い幅は左** (同じ HTML、CSS が切り替える) | ハンバーガーの中だけ / 6 つ以上 / 画面ごとに位置が変わる / いまいる所が分からない |
| 14 | 自分・ログアウト | **画面の右上に `.cpos-usermenu`** (右上は自分だけ。事業所は左) (氏名を押すと開く)。中身は上から「自分の情報」「ログアウト」。**ログアウトは CPOS に返す** (`/logout` → CPOS のログアウト)。氏名は必ず出す (誰で入っているかが分かる) | 画面の下や設定の奥に隠す / アプリ独自のログイン・パスワード変更 / 誰で入っているか分からない |
| 16 | 文字の大きさ | **端末の設定に追随した上で、アプリ内でも 3 段階 (標準 / 大 / 特大) 変えられる**。置き場は**設定の画面 (`<div data-cpos-text-size></div>` を置くだけ)**。選んだ大きさは**その端末に覚える** (当面はローカル保存。CPOS のユーザー設定に入ったらそちらを優先し、端末をまたいで揃うようにする)。`<script src="/cpos-ui.js" defer>` を読む | アプリで変えられない (端末の設定を知らない人が多い) / 置き場が画面ごとに違う / 覚えない |
| 17 | 多言語 (将来) | **今は日本語だけでよいが、後で訳せる形で書く**: `<html lang="ja">`、画面の文字はテンプレート/定数に集める (`if` の中に散らさない)、日付と数値は `Intl` で作る (「9月28日」を手で組まない)、**文字が 2 倍に伸びても折り返して壊れない** (幅を文字数で固定しない)、画像に文字を焼き込まない。CSS は左右でなく `inline-start / inline-end` で書く (`cpos-ui.css` はそうしてある) | 文字をコードのあちこちに直書き / 固定幅のボタン / 日付を手で組む / 画像に文字 |
| 15 | 設定 | **アプリは「そのアプリ固有の設定」しか持たない** (例: 既定の事業所、一覧の並び)。氏名・連絡先・パスワード・権限・文字サイズは持たない (氏名などは CPOS、文字サイズは端末の設定)。設定は `.cpos-usermenu` から 1 枚の `設定` 画面へ | 個人情報をアプリ側に持つ / アプリ独自の文字サイズ設定 / 設定がナビにもメニューにも無い |

### 守る 9 つ (どれも WCAG 2.2 AA か現場の要件。好みではない)
1. **`<meta name="viewport" content="width=device-width,initial-scale=1">` を必ず書く。**
2. **本文 16px (1rem)。px 固定で書かない。** 小さくしてよいのは補足だけ (`.cpos-sub` = 0.875rem)。端末の文字サイズ設定に追随する (CSS が `-apple-system-body` を入れてある)。
3. **押せるものは 44×44px 以上、間隔 8px 以上** (`.cpos-btn` がその大きさ)。
4. **文字と地のコントラスト 4.5:1 以上。色だけで伝えない** (状態は色 + 文字。`.cpos-badge` は文字を持つ)。
5. **幅 360px で全機能が使えて、横スクロールしない。** 表は `.cpos-table` を使う (狭い幅で自動的に 1 行 1 カードになる)。
6. **事業所名を画面の上に常に出す** (`.cpos-appbar` の `.cpos-facility`)。切り替えは一覧から選ぶ。
7. **`window.confirm` / `alert` / `prompt` を使わない。** 確認は `.cpos-dialog`。
8. **確認を出すのは取り消せない操作だけ** (削除・送信・確定・締め)。保存・編集・状態変更には出さない。
9. **キーボードだけで操作でき、どこにいるか見える** (`:focus-visible` の枠を消さない)。

### 画面の型 (既定 `standard`)
- **骨格**: 上に `.cpos-appbar` (左: アプリ名 + 必要なら事業所か `.cpos-scope` / 右端: `.cpos-usermenu`)。貼り付けたいときだけ `.cpos-pinned`、行き先は `.cpos-nav` (狭い幅は下、広い幅は左)、中身は `.cpos-page`。1 画面 1 仕事。
- **探す**: `.cpos-search` の欄 1 本 (即時絞り込み)。条件は `.cpos-chip` を並べる。条件が 5 つを超えるなら `<details>` に畳む (中でも「適用」ボタンは置かない)。
- **一覧**: `.cpos-table` (広い幅 = 表、狭い幅 = カード)。状態は `.cpos-badge`。0 件は空白にせず `.cpos-empty` (理由 + 次の一手)。
- **入力と保存**: `.cpos-field` (ラベル + 補足 + 入力 + `.cpos-error`)。**保存は `.cpos-savebar`** — 1 文字でも直すと画面上部に「未保存の変更 / 破棄 / 保存」が出て、保存するまで消えない (押し忘れと誤離脱を防ぐ)。保存したら `.cpos-snackbar` で「保存しました」。
- **取り消せない操作**: `.cpos-dialog` を 1 回。ボタンは動詞 (「削除する」/「やめる」)、「OK」「はい」を使わない。危険な方は `.cpos-btn.danger`。
- **状態**: 画面全体のことは `.cpos-banner` (情報 / 注意 / 危険)、操作の結果は `.cpos-snackbar`、入力の誤りは `.cpos-error` (欄の直下)。読み込み中は `.cpos-skeleton`。
- **ボタンの位置**: **意思決定 (保存・確定・送信) は右、取消・戻るは左。** 1 画面に `.cpos-btn.primary` は 1 つ。

### 文言
- ボタンは動詞 (「保存」「削除」「記録を書く」)。見出しは名詞。敬体で短く。
- 用語は `docs/GLOSSARY.md` で 1 つに (利用者 / 職員 / 事業所 / 要介護度)。「ユーザー」「入居者」を混ぜない。
- エラーは「何が起きたか」+「どうすればよいか」。技術用語 (401・null・API) を画面に出さない。
- 絵文字・英語の UI 文言を使わない。値が無い項目は空白でなく「未設定」。

### 決めきらないものは聞く
規約にすると全アプリが縛られるものは、規約に書かず **`create` の質問**にしてある (例: 「事業所の切り替えをヘッダに固定表示しますか」= `--facility-pinned`)。
現場や画面の性格で答えが変わるものは、これからもこの形で増える。

### この規約はまだ育っている
`npx github:loogo-inc/cpos-kit update` は、**規約が変わったときだけ**「この画面を基礎 UI に合わせますか？」と聞く (CPOS 追随の質問とは別。見た目と操作が変わるので分けてある)。
- **断ってよい。** 断った回は何もしないが、AGENTS.md の本文は最新になる。**次に規約が変わればまた聞く** (毎回の update で聞くのではなく、変わった回だけ)。
- 規約そのものが要らないなら `remove --apply`。以後この質問は出ない (版が上がったときに 1 行だけ「入れるなら adopt」と出る)。
